# Security policy

## Reporting a vulnerability

Report a vulnerability in the Shor Admin Panel privately, through GitHub's private vulnerability reporting, on [this repository's form](https://github.com/ShorRP/Admin_Panel/security/advisories/new). The form asks for a summary, the details, a proof of concept and the impact, as GitHub's docs describe (https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability, read 2026-10-25).

Never report a vulnerability through a public issue, a pull request, a discussion, or a message on Shor's Discord server: anyone could read it before it is fixed.

## Supported versions

Only the panel that runs in production, deployed from `main`, gets fixes. The panel has no version numbers and no tags: a fix ships with the merge into `main` that carries it (`CLAUDE.md`, **Delivery**).
