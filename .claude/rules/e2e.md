# The end-to-end tests

How an end-to-end test is written: the fake Discord, the fixtures, the console check and the responsive checks. `CLAUDE.md`, **Feedback loops**, says how to run it, and **Testing**, **Layers**, what it covers. The citations, measures and trials behind this rule are in `docs/e2e.md`; a flow whose test title says it plainly has no other description.

## Tests run one by one

- `fullyParallel: true` hands the tests to the workers one at a time, so a file's tests run on different workers, in no order, and `--shard` splits them between jobs (#488, #489). A test never depends on another of its file, on its order or on a module variable: each gets its own Discord server through the fixtures, or it passes or fails by where the scheduler put it. `playwright.config.test.ts` keeps the option set (`docs/e2e.md`, **Running the tests one by one**).

## The server and the fake Discord

- `next.onFetch` answers the server's calls to Discord by handing each request to the HTTP adapter over that test's own fake. It needs `experimental.testProxy`, which `next.config.ts` sets only when `E2E_TEST_PROXY` is `1`: the `webServer` of `playwright.config.ts` alone sets it, the build refuses it on Vercel, and `next.config.test.ts` proves both. A request that carries `next-test-proxy-port` then sends the server's `fetch` calls to `localhost`, so the variable stays unset everywhere else. `next start` loads `next.config.ts` again, so end to end runs over the last `pnpm build`, made without the variable (decided by the agent on 2026-11-12, on #449, for Gilles to review, since the statement moved here from `CLAUDE.md` whole).
- The `webServer` of `playwright.config.ts` waits on the port alone, through a TCP connection, since an HTTP request would carry no `next-test-proxy-port`, and its placeholder variables win over `.env.local`'s (`docs/e2e.md`, **The server and the fake Discord**).
- Next.js's `next` fixture marks only the requests of a test that uses it, so `e2e/fixtures.ts` gives every test, through automatic fixtures, its own `FakeDiscord` behind the adapter, built from the `discordState` option the test sets and given the archives channel of the placeholder, which stays empty unless the test poses archives in it, and the console check below. Every other file of `e2e/` takes `test` and `expect` from it (`eslint.config.mjs`, `admin-panel/e2e-fixtures`).
- Playwright's `request` fixture carries no `next-test-proxy-port`, so a server call made for it reaches the real network with the placeholder values: a flow drives `page`. The exceptions call no Discord, through `page.request` with no redirect followed, since `page.goto` would follow `/login` on to the real Discord: the visitor without a session, whose `/blocked-words` only the proxy answers, the `200` of `/privacy`, the 307 of `/`, which `next.config.ts` sends before the proxy, and the favicon, a static file.
- The browser's leg of OAuth never reaches `discord.com/oauth2/authorize`, since Playwright runs a route handler only for the first URL of a redirect: the `logIn` fixture routes `/login` itself, fetches the panel's answer without following it, checks that it points to Discord's authorize URL, and fulfills it in place with its `state` cookie; the test then opens `/login/callback` with that `state` and a code the fake issued (Gilles, 2026-10-26, on #10).

## The fixtures

- `checkAccessibility`: call it on each page a test crosses, once what `<Suspense>` streams shows, and after each write's toast or message, but on `/blocked-words` where `logIn` lands on the way to another page, which the login and blocked-word flows check. It waits for the page's `load` (`waitForLoad: false` where calls are held, as the skeleton test does), runs axe's WCAG 2.2 A and AA rules in light then in dark under `page.emulateMedia`, each time once every animation of `document.getAnimations()` has finished, and asserts that the body's background differs between the two, so that the dark run never checks light again. On a page whose theme a staff member chose, it runs axe once, in that theme, and compares no backgrounds (#225). Last it narrows the viewport to 360 px, where `scrollWidth` must not exceed `clientWidth`, unless `narrow: false` skips it (Gilles, 2026-11-16, on #490).
- Before each axe run it waits for the page to have a title: Next.js mounts the `<title>` anew with each response, so the page has none now and then, and axe's `document-title` reads `document.title`. The wait goes if Next.js stops keying the head's elements with the request's ID. `e2e/check-accessibility.test.ts`, which tests a fixture and no flow, proves it (decided by the agent on 2026-11-12, on #449, for Gilles to review; the gap's measure and the trial are in `docs/e2e.md`, **The fixtures**).
- `toast` finds a toast by its accessible name in the region « Notifications », or every toast when it names none; `readToast` waits for a write's toast, then presses F6, which focuses the region and pauses the toasts' timers, so that the checks that follow, which can outlast a toast's 5 s, still see it and its « Fermer » (#227; `docs/e2e.md`, **The fixtures**, says why the focus).
- `holdDiscord` holds every call the server then makes to Discord until the function it returns is called, so that a page shows its skeletons. A test releases it within the 10 s after which a call gives up (`.claude/rules/discord.md`, **Errors and retries**). While it holds, the page keeps streaming and fires no `load`, so a test waits for none, and the skeleton test waits for every stylesheet to have its `sheet` before it reads the pulse (#139; `docs/e2e.md`, **Gotchas**).
- `discordCdnRequests`, automatic, routes `https://cdn.discordapp.com/**` to a local SVG and records each URL it serves, since Chromium loads an image itself, through no `next.onFetch` (inferred): the avatar's test reads the record, and no test reaches the real CDN (#140).
- `prefetchedPaths` records the path of each request the page sends with `next-router-prefetch`. A flow that logs out reads it empty, so that a link's prefetch, which can reach `/login` after the logout (`.claude/rules/next-link-prefetch.md`), fails it on every run and not now and then (#153). `logOutWithScriptsHeld` (`e2e/log-out-with-scripts-held.ts`) logs out with the page's scripts held, and expects `/login/logged-out` and no `__Host-session`. Each flow asserts its links are in the viewport right before, since `isVisible()` reads the DOM and not the viewport.
- Every test runs under `reducedMotion: "reduce"`; a test that needs the animations asks for them through `test.use({ reducedMotion: "no-preference" })`, so that the animations' path meets the console check too (#134).
- At `load` a page is not complete: React still holds the content of each `<Suspense>` in hidden segments, `[id^="S:"]` and `template[id^="B:"]`, that a script reveals later through a view transition, and a control in them measures 0 by 0. A test that measures waits for `settle(page)` (`e2e/settle.ts`): the segments gone and `document.activeViewTransition` `null`, which `checkAccessibility`'s wait for the animations does not tell. A flow that changes the viewport of a page already shown goes through `resize`, which settles first, since Chromium aborts a view transition that a change of size cuts, with a `pageerror` that the console check refuses (#348). The line goes if Next.js or React stops holding a streamed boundary's content in hidden segments.
- `instantReveals`, `false` unless a file sets it, makes a streamed boundary show on the next frame: React's reveal clock `$RT` reads as `undefined`, so that no batch waits 300 ms for the last, and the view transition's pseudo-elements get animations of no duration (`docs/e2e.md`, **The fixtures**). It touches React's runtime in `e2e/responsive.test.ts` alone, which measures a settled page; every other flow meets the reveals' real timing, and `settle` stays as it is, still awaited (decided by the agent on 2026-11-16, on #493, for Gilles to review). `e2e/instant-reveals.test.ts` proves both. The option goes if React renames or drops `$RT`, which that test catches.

## The browser's console

- A browser console message at `error` or `warning`, or a `pageerror`, fails the test, a Content Security Policy violation included; a `console.log` fails none. The automatic fixture `browserConsole` collects them and asserts, once the test ends, that there are none (#63, #76).
- A test that expects a line declares it, by its exact text, through `browserConsole.expectProblems`: it then fails on any other line and on a declared one that never comes, in whatever order they come, and the fixture takes each declared line once however often it comes (#61). Chromium logs a document that answers 404 as « Failed to load resource: the server responded with a status of 404 (Not Found) ».
- A flow that shows `error.tsx` declares #441 (`console.error: Error: ` and `minifiedReactError(441)`): React's production error for an error row of the RSC stream, printed once as the error page appears, so every read that fails brings it. It declares #419 too, as a `pageerror`, only where it clicks « Réessayer », whose click always brings it, since a declared line that never comes fails the test (#61; `docs/e2e.md`, **The browser's console**).
- A flow that makes a read fail once fails a method that only the page reads: `failNext` keeps one failure per method, and the layout's count of blocked words reads the AutoMod rules too, so it would take the failure and swallow it (the audit log's flow fails `getAuditLog`).
- The console of `next start` fails nothing: the server prints a failed read by design (`.claude/rules/monitoring.md`, **What is logged**).

## The responsive checks

- `e2e/responsive.test.ts` crosses `STAFF_PAGES` and `PUBLIC_PAGES` at 360, 390, 768 and 1,024 px: each page and width is one test, which checks the sideways scroll, the 44 px targets and axe through `expect.soft`, so that a failure hides no other. Axe runs at 360, 768 and 1,024 px alone, one for each layout of the navigation, with `narrow: false`, since the test crosses 360 px and measures `horizontalOverflow` at its own width (Gilles, 2026-11-16, on #490). Each test logs in on its own (`docs/e2e.md`, **The responsive crossing**). A page that joins the panel joins the matching list in the same change (decided by the agent on 2026-11-12, on #449, for Gilles to review, since the lists outgrew the nine pages that #355 counted). A staff session reaches the error pages only through an unknown URL or a failed read, so `the login, error and privacy pages at <width> px` measures them.
- A page whose filters show as chips is crossed twice, bare and with filters set, and its filter sheet, which exists under 768 px alone, gets an entry of `FILTER_SHEETS`, a test of its own that opens it and measures it.
- The 1,024 px screen alone has a touch screen, since it is the one width where `touch:` holds through the pointer alone (`holdsTouch` asserts it).
- An entry's `fixme: true` skips its 44 px assertion and adds a `fixme` annotation until that page delivers it, so that the other checks run from the day a page joins (Gilles, 2026-11-16, on #490, after #355).
- The 44 px check is `smallTargets`, defined in `docs/e2e.md`, **The responsive crossing**, which says what counts as a target: the label of a radio or a checkbox, not its native `<input>`, and a link alone in its element, not one inside a sentence.
- A flow that measures one page's own controls, as `the record at <width> px` does, passes `smallTargets` the root `main`, since it takes `body` by default, so that the navigation's own targets, which #356 delivered, are left to the page-wide 44 px test (decided by the agent on 2026-11-03, on #361, for Gilles to review; `docs/e2e.md`, **The responsive crossing**, says why).

## Gotchas

- With `cacheComponents`, the page a navigation leaves stays in the document, hidden with `display: none` inside React's `<Activity>`, so a locator of every `h1, h2` still finds the hidden page's: a test that reads every element of a kind keeps the visible ones, through `filter({ visible: true })` (#133).
- A logout that starts before React has hydrated the page's metadata can leave `/login/logged-out` with two identical `<link rel="icon">` (#169), so `e2e/favicon.test.ts` waits for one `href` among the page's icon links and reads the first one the staff page did not hold (#263). The tolerance goes once an update of Next.js or React adopts or removes the server's link on a client mount (`docs/e2e.md`, **The favicon flow**, says how to tell; decided by the agent on 2026-11-12, on #449, for Gilles to review).
- After a full page load, such as the one the panel's link to `/` starts, a test waits for the page's `load` before it submits a form: otherwise Playwright can click while the page still streams, the browser posts the Server Action's form natively with no `Next-Action` header, and the document it leaves throws React's error #412 or #419, which a `<Suspense>` under a `<ViewTransition>` makes likelier (#134; `docs/e2e.md`, **Gotchas**).
- A test that maps each animation of a write to its element records every `view-transition-name` through a `MutationObserver` an init script installs (`e2e/blocked-words.test.ts`), since React takes the names off while the animations still run when an update, such as the write's toast, comes mid-transition (`docs/ui.md`, **View transitions**; inferred).
- Chromium hands assistive technologies the text under `text-transform: uppercase` in capitals, while `getByRole` names an element from the DOM's text, as written: an end-to-end name proves the DOM's text, not what a screen reader receives (inferred, #232; `docs/e2e.md`, **Gotchas**).
- While a modal Sheet is open, the page behind it is hidden from the accessibility tree, so a `getByRole` locator of a link behind it finds nothing, and `isVisible()` on it answers `false`: a flow that logs out from the bar's menu reads its links in view with role locators first, then hands `logOutWithScriptsHeld` locators by CSS, such as `main a[href]` and `main button[aria-haspopup="dialog"]` (#359). The line goes if Base UI stops hiding the page behind a modal from the accessibility tree, or once `logOutWithScriptsHeld` finds its links itself.
- An `sr-only` element is visible to Playwright: its box is 1 px by 1 px, which `toBeVisible` accepts, so a test that proves a text is hidden below a width reads the box's width (`e2e/responsive.test.ts`, #356).
- Two `setViewportSize` calls with no frame between them can reach the page as one `resize` event: prove a narrowing by what the page does, not by counting events (#492).
- On Windows, two Node processes read `Date.now()` a few milliseconds apart, so the refused-timeout flow of `e2e/sanctions.test.ts`, whose 28 days sit on the fake's limit, fails on a 400 now and then (`docs/e2e.md`, **Gotchas**).
