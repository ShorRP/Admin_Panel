# The end-to-end tests

How an end-to-end test is written: the fake Discord behind the server, the fixtures every test gets, the console check and the responsive checks. `CLAUDE.md`, **Feedback loops**, says how to run it, and **Testing**, **Layers**, what it covers. The citations, measures and trials behind this rule are in `docs/e2e.md`; a flow whose test title says it plainly has no other description. CI installs Chromium alone, with no system package (`.claude/rules/ci.md`, **CI**).

## The server and the fake Discord

- `next.onFetch` answers the server's calls to Discord by handing each request to the HTTP adapter over that test's own fake. It needs `experimental.testProxy`, which `next.config.ts` sets only when `E2E_TEST_PROXY` is `1`: the `webServer` of `playwright.config.ts` alone sets it, the build refuses it on Vercel, and `next.config.test.ts` proves both. A request that carries `next-test-proxy-port` then sends the server's `fetch` calls to `localhost`, so the variable stays unset everywhere else. `next start` loads `next.config.ts` again, so end to end runs over the last `pnpm build`, made without the variable (decided by the agent on 2026-11-12, on #449, for Gilles to review, since the statement moved here from `CLAUDE.md` whole).
- The `webServer` of `playwright.config.ts` waits on the port alone, through a TCP connection, since an HTTP request would carry no `next-test-proxy-port`, and its placeholder variables win over `.env.local`'s (`docs/e2e.md`, **The server and the fake Discord**).
- Next.js's `next` fixture marks only the requests of a test that uses it, so `e2e/fixtures.ts` gives every test, through automatic fixtures, its own `FakeDiscord` behind the adapter, built from the `discordState` option the test sets and given the archives channel of the placeholder, which stays empty unless the test poses archives in it, and the console check below. Every other file of `e2e/` takes `test` and `expect` from it (`eslint.config.mjs`, `admin-panel/e2e-fixtures`).
- Playwright's `request` fixture carries no `next-test-proxy-port`, so a server call made for it reaches the real network with the placeholder values: a flow drives `page`. The exceptions call no Discord, through `page.request` with no redirect followed, since `page.goto` would follow `/login` on to the real Discord: the visitor without a session, whose `/blocked-words` only the proxy answers, the `200` of `/privacy`, the 307 of `/`, which `next.config.ts` sends before the proxy, and the favicon, a static file.
- The browser's leg of OAuth never reaches `discord.com/oauth2/authorize`, since Playwright runs a route handler only for the first URL of a redirect: the `logIn` fixture routes `/login` itself, fetches the panel's answer without following it, checks that it points to Discord's authorize URL, and fulfills it in place with its `state` cookie; the test then opens `/login/callback` with that `state` and a code the fake issued (Gilles, 2026-10-26, on #10).

## The fixtures

- `checkAccessibility`: call it on each page a test crosses, once what `<Suspense>` streams shows, and after each write's toast or message, but on `/blocked-words` where `logIn` lands on the way to another page, which the login and blocked-word flows check. It waits for the page's `load` (`waitForLoad: false` where calls are held, as the skeleton test does), runs axe's WCAG 2.2 A and AA rules in light then in dark under `page.emulateMedia`, each time once every animation of `document.getAnimations()` has finished, and asserts that the body's background differs between the two, so that the dark run never checks light again. On a page whose theme a staff member chose, it runs axe once, in that theme, and compares no backgrounds (#225). Last it narrows the viewport to 360 px, where `scrollWidth` must not exceed `clientWidth`.
- Before each axe run it waits for the page to have a title: Next.js mounts the `<title>` anew with each response, so the page has none now and then, and axe's `document-title` reads `document.title`. The panel lives with the gap, which only a patch of Next.js could close (decided by the agent on 2026-10-30, on #161, for Gilles to review). The wait goes if Next.js stops keying the head's elements with the request's ID. `e2e/check-accessibility.test.ts`, the one test of a fixture rather than of a flow, proves it (decided by the agent on 2026-11-12, on #449, for Gilles to review, where the gap's measure and the trial are in `docs/e2e.md`, **The fixtures**).
- `toast` finds a toast by its accessible name in the region « Notifications », or every toast when it names none; `readToast` waits for a write's toast, then presses F6, which focuses the region and pauses the toasts' timers, so that the checks that follow, which can outlast a toast's 5 s, still see it and its « Fermer », which Base UI hides from assistive technologies until the region is focused or hovered (#227).
- `holdDiscord` holds every call the server then makes to Discord until the function it returns is called, so that a page shows its skeletons. A test releases it within the 10 s after which a call gives up (`.claude/rules/discord.md`, **Errors and retries**). While it holds, the page keeps streaming and fires no `load`, so a test waits for none, and the skeleton can show before the page's stylesheets apply (inferred): the skeleton test waits for every `link[rel="stylesheet"]` to have its `sheet` before it reads the pulse (#139).
- `discordCdnRequests`, automatic, routes `https://cdn.discordapp.com/**` to a local SVG and records each URL it serves, since Chromium loads an image itself, through no `next.onFetch` (inferred): the avatar's test reads the record, and no test reaches the real CDN (#140).
- `prefetchedPaths` records the path of each request the page sends with `next-router-prefetch`. A flow that logs out reads it empty, so that a link's prefetch, which can reach `/login` after the logout (`.claude/rules/next-link-prefetch.md`), fails it on every run and not now and then (#153). `logOutWithScriptsHeld` (`e2e/log-out-with-scripts-held.ts`) holds the page's scripts, reads that the links it is given are still visible when the first is released, clicks the logout, expects `/login/logged-out` and no `__Host-session`. Each flow asserts its links are in the viewport right before, since `isVisible()` reads the DOM and not the viewport. A sanction's link to `/records/<id>` may be caught without the hold (inferred).
- Every test runs under `reducedMotion: "reduce"`; a test that needs the animations asks for them through `test.use({ reducedMotion: "no-preference" })`, so that the animations' path meets the console check too (#134).
- At `load` a page is not complete: React still holds the content of each `<Suspense>` in hidden segments, `[id^="S:"]` and `template[id^="B:"]`, that a script reveals later through a view transition, and a control in them measures 0 by 0. A test that measures waits for `settle(page)` (`e2e/settle.ts`): the segments gone and `document.activeViewTransition` `null`, which `checkAccessibility`'s wait for the animations does not tell. A flow that changes the viewport of a page already shown goes through `resize`, which settles first, since Chromium aborts a view transition that a change of size cuts, with a `pageerror` that the console check refuses (#348). The line goes if Next.js or React stops holding a streamed boundary's content in hidden segments.

## The browser's console

- A browser console message at `error` or `warning`, or a `pageerror`, fails the test, a Content Security Policy violation included; a `console.log` fails none. The automatic fixture `browserConsole` collects them and asserts, once the test ends, that there are none (#63, #76).
- A test that expects a line declares it, by its exact text, through `browserConsole.expectProblems`: it then fails on any other line and on a declared one that never comes, in whatever order they come, and the fixture takes each declared line once however often it comes (#61). Chromium logs a document that answers 404 as « Failed to load resource: the server responded with a status of 404 (Not Found) ».
- A flow that shows `error.tsx` declares #441 (`console.error: Error: ` and `minifiedReactError(441)`, in `e2e/minified-react-error.ts`): React's production error for an error row of the RSC stream, printed once as the error page appears, so every read that fails brings it. It declares #419 too, as a `pageerror`, only where it clicks « Réessayer », whose click always brings it, since a declared line that never comes fails the test (#61; `docs/e2e.md`, **The browser's console**).
- A flow that makes a read fail once fails a method that only the page reads: `failNext` keeps one failure per method, and the layout's count of blocked words reads the AutoMod rules too, so it would take the failure and swallow it (the audit log's flow fails `getAuditLog`).
- The console of `next start` fails nothing: the server prints a failed read by design (`.claude/rules/monitoring.md`, **What is logged**).

## The responsive checks

- `e2e/responsive.test.ts` crosses `STAFF_PAGES` and `PUBLIC_PAGES` at 360, 390, 768 and 1,024 px, over one Discord server with a role of each kind, a member with a role, a banned account and two blocked words: for each page and width, one test fails on a page that scrolls sideways and on axe, and one on a control under 44 px. A page that joins the panel joins the matching list in the same change (decided by the agent on 2026-11-12, on #449, for Gilles to review, since the lists outgrew the nine pages that #355 counted). The error pages are not crossed, since a staff session reaches them only through an unknown URL or a failed read: `the login, error and privacy pages at <width> px` measures them.
- A page whose filters show as chips is crossed twice, bare and with filters set, and its filter sheet, which exists under 768 px alone, gets an entry of `FILTER_SHEETS`, a test of its own that opens it and measures it.
- The 1,024 px screen alone has a touch screen, since it is the one width where `touch:` holds through the pointer alone (`holdsTouch` asserts it).
- An entry's `fixme: true` makes its 44 px check a `test.fixme` while the ticket of that page has not delivered it, so that the sideways scroll and axe checks run from the day a page joins (decided by the agent on 2026-11-03, on #355, for Gilles to review, since #355 asks for each page in `test.fixme` and its other checks pass today).
- The 44 px check reports each control that `TARGET_SELECTOR` lists whose box is under 44 px, but for one that is `sr-only`, `aria-hidden`, `inert` or invisible, and a link inside a sentence.
- The label of a radio or a checkbox is the target, and the native `<input>` is not, since a native checkbox is 16 px wide, its label is what a finger hits, and a timeout's radio button covers its label (decided by the agent on 2026-11-03, on #355, for Gilles to review).
- A link is inside a sentence when it is inline, in a `p`, `li`, `dd` or `span` that holds more text than the link, so that a link that stands alone in a `<p>` with a count would escape it (decided by the agent on 2026-11-03, on #355, for Gilles to review).
- A flow that measures one page's own controls, as `the record at <width> px` does, passes `smallTargets` the root `main`, since it takes `body` by default, so that the navigation's own targets, which #356 delivered, are left to the page-wide 44 px test (decided by the agent on 2026-11-03, on #361, for Gilles to review, since #361 names no flow of its own and the navigation's targets kept the page-wide test red until #356).

## Gotchas

- With `cacheComponents`, the page a navigation leaves stays in the document, hidden with `display: none` inside React's `<Activity>`, so a locator of every `h1, h2` still finds the hidden page's: a test that reads every element of a kind keeps the visible ones, through `filter({ visible: true })` (#133).
- A logout that starts before React has hydrated the page's metadata can leave `/login/logged-out` with two identical `<link rel="icon">`, so that a locator of `link[rel="icon"]` resolves to 2 elements (#169). `e2e/favicon.test.ts` waits until the page's icon links hold one `href`, and marks the staff page's links before the logout to read the first unmarked one after it, since the staff page's link can outlive the navigation (#263). The tolerance goes once an update of Next.js or React adopts or removes the server's link on a client mount, which `docs/e2e.md`, **The favicon flow**, says how to tell (decided by the agent on 2026-11-12, on #449, for Gilles to review, where that flow's observations are in `docs/e2e.md`).
- After a full page load, such as the one the panel's link to `/` starts, a test waits for the page's `load` before it submits a form: otherwise Playwright can click while the page still streams, the browser posts the Server Action's form natively with no `Next-Action` header, and the document it leaves throws React's error #412, `Connection closed.`, or #419. A `<Suspense>` under a `<ViewTransition>` widens that window, since React's streaming runtime reveals it through `document.startViewTransition` (#134).
- Chromium hands assistive technologies the text of an element under `text-transform: uppercase` in capitals, while Playwright's `getByRole` names an element from the DOM's text, as written: an end-to-end name proves the DOM's text, not what a screen reader receives, and an overline reaches one in capitals, which a screen reader may spell out letter by letter for a short word (inferred, not checked with a screen reader, #232).
- While a modal Sheet is open, the page behind it is hidden from the accessibility tree, so a `getByRole` locator of a link behind it finds nothing, and `isVisible()` on it answers `false`: a flow that logs out from the bar's menu reads its links in view with role locators first, then hands `logOutWithScriptsHeld` locators by CSS, such as `main a[href]` and `main button[aria-haspopup="dialog"]` (#359). The line goes if Base UI stops hiding the page behind a modal from the accessibility tree, or once `logOutWithScriptsHeld` finds its links itself.
- An `sr-only` element is visible to Playwright: its box is 1 px by 1 px, which `toBeVisible` accepts, so a test that proves a text is hidden below a width reads the box's width, as the navigation's flow does for the group titles of the rail (`e2e/responsive.test.ts`, #356).
