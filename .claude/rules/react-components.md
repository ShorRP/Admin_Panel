# Gotchas of React, Base UI and `next/script` in components

- An inline `next/script` with `beforeInteractive` runs neither in the head nor before the page is read, whatever Next.js's docs say (`node_modules/next/dist/docs/01-app/03-api-reference/02-components/script.md:69`, `:156`): in the App Router, it renders in the body as `self.__next_s.push(…)`, which Next.js's bootstrap, an `async` chunk, runs before it hydrates, so the page can be read and painted first (`.claude/rules/ui-theme.md`, **The theme a staff member chooses**, #225). A script that must run before the body is read is a plain `<script>` in the root layout's `<head>`, whose text React writes as it is.
- A Base UI `Close` that renders a link, `nativeButton={false}` with `role={undefined}` as the bar's menu writes it, stays a link in a client component and becomes `role="button"` when a Server Component writes it: in `FilterSheetForm`, the Sheet's « Réinitialiser » was a `button` in the page's accessibility tree, and `getByRole("link", { name: "Réinitialiser" })` found none (`e2e/audit-log.test.ts`, 2026-11-03, #359). Base UI adds `role="button"` to what `nativeButton={false}` renders (`node_modules/@base-ui/react/internals/use-button/useButton.js:186`), and an `undefined` prop is inferred to be lost on its way from a Server Component, where the same prop works in a client one. So a link rendered through a `Close` in a Server Component says `role="link"`. The line goes once a copy of `FilterSheetForm` with `role={undefined}` renders a link in the accessibility tree, which a Base UI update could bring (inferred), or if the Sheet's link is written in a client component.
- React's synthetic events bubble through a portal to the React ancestors, not to the DOM's: a Base UI Sheet or Dialog whose content holds a `next/form`, rendered as a child of another `next/form`, runs both `onSubmit`s. **Read in the code** (Next.js 16.4.2): `onFormSubmit` takes the fields of `event.currentTarget`, the form its handler is on, and calls `router.push` with their address (`node_modules/next/dist/client/app-dir/form.js:88-140`). **Observed** (2026-11-03, `pnpm test:e2e e2e/account-filters.test.ts`, #360): on a throwaway build that put the list of accounts' `FilterSheetContent` inside the page's `<Form>`, the Sheet's « Appliquer » landed on `/records?query=zzz&role=&standing=members&joined=&created=&bots=&sort=`, the page form's address with the text typed in it, where the Sheet's choices asked for a role and a sort. **Inferred**: the outer handler runs after the inner one, so its `router.push` comes last and wins. So the `<Sheet>`'s root wraps the page's form and the Sheet's content is the form's sibling (`src/records/account-search-form.tsx`). The line goes if `next/form` stops pushing for a submit that React bubbled from another form.
