# Account list

The list of every account of the Discord server at `/records`, members and banned accounts mixed, for the staff members who hold a role of `MODERATION_ROLE_IDS` (ADR 0005): ranked by name, or by arrival or by highest role, 25 a page with their total, searched by the start of a name, filtered by role, standing, arrival and age of the account, with the bot accounts hidden unless they ask (#322, #324). An ID or a mention opens the record (`.claude/rules/records.md`). The tests of `src/records/` and `e2e/account-*.test.ts` name each case, the filters and the sorts among them. The calls per view, the departures from the mockup, the measures and the trials are in `docs/records.md`: read it before adding a read to the page.

## Reading

- The list reads every member and every banned account, 1,000 a call, and the roles, the three in parallel after the staff check; the search, the filters and the sort run in memory on what they gave, so that a search costs no call (#322, #323, #324; `docs/records.md`, **Calls per view**). Above 10,000 accounts, reading them all at each view is to be reviewed (#317).
- The page creates the staff check's promise and the roles', which the form's `<Suspense>` and the list's share, so that the form, which lists the roles, shows before the members are read. `listAccounts` answers an ID or a mention before it awaits the roles, and the page redirects to the record, the roles' call already started for the form, so that every view reads the roles once (#324). The one promise, in place of a second `listRoles` call for the form, is decided by the agent on 2026-11-02, on #324, for Gilles to review.
- A read that fails is thrown and `error.tsx` replaces the whole page, the search field with it: a 403 of code 50001 for want of the Server Members Intent, and a failed read of the roles, are panel errors and alert (#322, #317, #324; `CLAUDE.md`, **Read failures**).
- `resolveAccounts`, `accountNames` and `readAllMembers` serve the name filters of the support tickets and of the Bot log too (`.claude/rules/support-tickets.md`, **Accounts and counts**; `.claude/rules/bot-log.md`, **Reading**), and `accountIdOf` the audit log's (`.claude/rules/audit-log.md`, **The filters**).

## Filters and order

- The URL holds the search and the choices, in English since a URL counts as a file name: `query`, `role`, `standing`, `joined`, `created`, `bots`, `sort`, and `page`, none for the first. A value that is none of the choices, a repeated one, a role that the Discord server does not list, `@everyone` included, and a page that is no integer, is below 1 or lies past the last count as absent, so that the first page shows (`CLAUDE.md`, **Validation**). `accountListHref` writes the choices that are set alone, in that order, then the page.
- The first choice of each select, « Tous les rôles », « Tous les comptes », « Toutes les dates », « Tous les âges », « Masqués » and « Nom », has the empty value and stands for no filter: `next/form` writes every control into the URL, so a submit sends `role=` and the five others empty, which counts as absent, as the audit log's form does with `author=` (#321). #324 asks that neither the form nor the links write the first choice, which no native GET form can without client logic (decided by the agent on 2026-11-02, on #324, for Gilles to review).
- The role choice lists « Tous les rôles », « Aucun rôle », then each role but `@everyone` from the highest, where #324 lists « Aucun rôle » after the roles, which leaves it at the foot of a list of some forty (decided by the agent on 2026-11-02, on #324, for Gilles to review).
- `filterAccounts` keeps the accounts that pass the search and every choice, in AND. The text starts the username, the global name or the nickname of a member, or the username or the global name of a banned account, whatever the case (`lowerCaseNames`, which `resolveAccounts` shares). « Membres » keeps every member, timed out or not, since a timed-out member remains one (`GLOSSARY.md`, **Member**; #324's proposal); the other choices, the arrival's bounds, which are included or left out, and the sorts are tested at their edges (`list-accounts-filters.test.ts`, `list-accounts-sorts.test.ts`, `months-ago.test.ts`).
- « Exclus en ce moment » is #324's own wording, which stands though `GLOSSARY.md` avoids « exclusion » alone for a timeout: the label names the standing of a member whose timeout runs, as « Exclu jusqu’au <date> » does (decided by the agent on 2026-11-02, on #324, for Gilles to review, with no change to `GLOSSARY.md`).
- The arrival and the age of the Discord account count in UTC, while the panel shows Paris time, so that a member who joined a few hours after a bound in Paris time may sit on either side of it (decided by the agent on 2026-11-02, on #324, for Gilles to review).
- « Comptes de bot » hides every account that Discord flags `bot`, the panel's own application among them, until « Affichés ». These are the glossary's **Bot account**, not its **Bot**, which is Shor's alone, so the label says « Comptes de bot » where #324 writes « Bots », the code names them `botAccount` and `isBotAccount`, and the URL keeps `bots` (decided by the agent on 2026-11-02, on #324, for Gilles to review, with the entry **Bot account** added to `GLOSSARY.md`).
- By default the accounts run by the name they show, a member's nickname, else global name, else username, a banned account's global name, else username, whatever its case but not its accents, through `Intl.Collator("fr-FR", { sensitivity: "accent" })`, where a comparison of UTF-16 units would put « Éclair » after « Zed », then by ID, so that two accounts of one name keep their page from one view to the next (the collator decided by the agent on 2026-11-02, on #322, for Gilles to review). The sorts by arrival and by highest role put the banned accounts and the members with no date or no listed role after the others, by name (the end of the arrival sorts is #324's proposal).

## The rows

- The overline over the rows, « 26–50 sur 312 », gives the ranks of the first and the last account of the page, an en dash between them, then the total, the numbers through `frenchNumber`, so that a page of one account gives its rank alone, « 312 sur 312 » (decided by the agent on 2026-11-02, on #322, for Gilles to review). « Heures de Paris. » follows the rows once, through `ParisHoursNote`, and only when a row shown is timed out (#232, #322, #324). `AccountPagination` gives the `Pagination` of `src/ui/` its label « Pages des comptes » and the addresses of `accountListHref` (#385; `CLAUDE.md`, **Theme**).
- An empty list says « Aucun compte ne correspond à ta recherche. » in an `EmptyListFrame`, a dashed box bordered in `input`, as the mockup draws it (decided by the agent on 2026-10-29, on #232, for Gilles to review), whatever hid the accounts, the bot accounts hidden by default included (the one sentence decided by the agent on 2026-11-02, on #324, for Gilles to review).
- A row is one link to the record through `recordHref`, shown to those who moderate alone, `accent` on hover (#221), with the badges under the name under `sm`. The avatar keeps `MemberAvatar`'s 32 px, where the mockup draws 38 (decided by the agent on 2026-10-29, on #232, for Gilles to review).

## The form

- `AccountSearchForm` is the page's one form, a GET `next/form` with `prefetch={false}` to `/records`: the search, under its label « Compte », which the mockup drops, then six native `<select>`s, each under a visible `Label`, then « Chercher », which sends no page and so leads to the first (#232, #324). `account-choices.ts` holds the six choices, which the Sheet's form and the chips read too.
- Under `md`, the six choices are `hidden`, kept in the form, so that a search sent from the page keeps the choices set, and « Filtres » and « Chercher » share a row in two equal columns; from `md` the choices take a basis of 11 rem and grow, so that three share a row at 768 px and four at 1,280 px (#324, #360).
- « Filtres » is a `FilterSheetTrigger` that counts the choices set, the search left out. It opens a Sheet from the bottom under `sm` and from the right from `sm`, 384 px at most, through the classes that `FilterSheetContent` takes for `rightFromSm`, important overrides of the bottom Sheet's own, which leave the copied Sheet as the CLI wrote it (decided by the agent on 2026-11-03, on #360, for Gilles to review).
- The Sheet holds a GET form of its own to `/records`, `AccountFilterSheetForm`: a hidden `query` with the search text of the URL, always sent, even empty, as the inline field sends it, the six choices under ids of their own, `account-sheet-*`, « Réinitialiser » and « Appliquer », so that it gives the address the inline form gives for the same choices, each parameter once. A search typed and not sent is lost when the Sheet is sent, since its hidden `query` is the URL's (Gilles, 2026-11-03, on #360). « Réinitialiser » keeps the search where the audit log's clears everything, since that page's form has no field to keep, and it resets the six choices, the sort included (decided by the agent on 2026-11-03, on #360, for Gilles to review).
- The root of the `<Sheet>` wraps the page's `<Form>`, whose row holds the trigger, and the Sheet's content is a sibling of that `<Form>`, not a child: React's synthetic `submit` bubbles through a portal to the React ancestors, so a Sheet form inside the page's would run the page's `onSubmit` too (`.claude/rules/react-components.md`). The root is keyed by the address `accountListHref` writes for the choices, as the blocked words' form is keyed by its query (`.claude/rules/blocked-words.md`, **Forms**), so that a move to other choices shows their values; that the browser's Back button needs the key too is inferred, not tried.
- The choices set show under the search, under `md`, as chips, `FilterChips`, named « Retirer le filtre État : Membres » from the field's label then the option's, `choiceChipsOf`: the labels are the fields', since the longest chip, « Âge du compte Discord : Moins de 30 jours », fits a 360 px screen (decided by the agent on 2026-11-03, on #360, for Gilles to review; `docs/records.md`, **Measures**).

## Badges

- `StandingBadge` says the standing of an account, a member, a timed-out member, a banned account or an account absent from the Discord server, after a dot, `aria-hidden` since the text says it; the list draws it beside each account and a record's header beside the account's name (#232, #233). « Exclu jusqu’au <date> » is #232's own wording, which stands though `GLOSSARY.md` avoids « exclusion » alone for a timeout: it avoids the word with no end, which could name a kick, and this label names the end (decided by the agent on 2026-10-29, on #232, for Gilles to review, with no change to `GLOSSARY.md`).
- It takes an `AccountStanding`, in `account-standing.ts`, the shape of a record's `Standing`, which a record's header passes as it is (#233). The list holds no absent account, which only its ID or its mention reaches, and they lead straight to its record (#232). `FoundAccount` carries it as `standing`, a member's read from the `communication_disabled_until` that the members' list returns, through `timeoutEndOf`, which a record's standing reads too (the union decided by the agent on 2026-10-29, on #232, for Gilles to review).
- A member's highest role shows in a `RoleBadge` in place of « Membre du serveur » (#323), with `StandingBadge`'s shape, which both take from `BADGE_CLASSES` and `BADGE_DOT_CLASSES`: a row shows the role alone, and the role then « Exclu jusqu’au <date> » for a member timed out, while a member with no role and a banned account keep `StandingBadge`. The dot takes the role's primary color through a `style`, since Tailwind reads no class built at run time and the Content Security Policy allows inline styles, and the neutral `muted-foreground` for a role with no color (https://docs.discord.com/developers/topics/permissions, read 2026-11-02; the neutral dot is #323's proposal). It ignores `secondary_color` and `tertiary_color`, so a gradient role shows its primary color, and a role's name wraps where it does not fit, so that a long one stays in its row.
- `rolesByHierarchy`, in `role-hierarchy.ts`, ranks roles from the highest to the lowest by `position` and, for two of the same position, by the lower ID first: Discord's documentation says only that « roles with the same position are sorted by id » (the same page), and discord.js's `Role#position` counts the role with the lower ID as the higher (`packages/discord.js/src/structures/Role.js`, read 2026-11-02), which is inferred to be Discord's own order, since two roles of one position were not tried on the test Discord server (decided by the agent on 2026-11-02, on #323, for Gilles to review).
- `highestRoleOf` relies on Discord not putting `@everyone`, whose ID is the Discord server's, in a member's `roles` (inferred, not tried), so a member whose `roles` held that ID would show an « @everyone » badge.

## Skeletons, responsive and tests

- `AccountSearchFormSkeleton` holds no field, so that nothing typed into a fallback is lost when the form replaces it, until the staff check and the roles' read are done (#324; `docs/records.md`, **Trials**); `FoundAccountsSkeleton` stands for the list, with nothing for the navigation under it (#232, #322, #324).
- `docs/responsive.md`, **`/records`**, specifies the page (#360); a later change must not break the badges under the name under `sm`, the second wrapping under the first, a row of 56 px at least under `touch`, the choices folded behind « Filtres » under `md`, and the Sheet that slides in only with motion, from the bottom under 640 px and from the right from 640 px (#232, #323, #324, #360; `CLAUDE.md`, **Motion**; `docs/records.md`, **Trials**).
- No link and no form of the page prefetches, since a prefetch can reach `/login` right after a logout (`.claude/rules/next-link-prefetch.md`): the rows, the form, the chips and the pagination's links set `prefetch={false}`, and `e2e/account-list.test.ts` logs out from page 5 with the navigation in view, through `logOutWithScriptsHeld`, and fails when one prefetches (`docs/records.md`, **Trials**).
- `listMembers` failing with the 403 of code 50001 shows `error.tsx` with neither the navigation nor the search field (`e2e/account-list.test.ts`).
