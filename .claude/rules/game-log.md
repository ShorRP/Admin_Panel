# The game log's page (#394, #395)

`/game-log`, under « Journaux » in the navigation, lists the lines that the game server's webhook posts in « 🔧・log-jeux » (`GLOSSARY.md`, **Game log**; ADR 0010, #381). It is built on the log components of `src/ui/` (`.claude/rules/ui.md`, **Shared components**), as the audit log and the Bot log are, reads the channel through `scanMessages` (`.claude/rules/discord-message-scan.md`), and is filtered by category, through pills, and by action, character, game account, target, cell, plugin, reason, text and period (**The filters**, #395). `docs/game-log.md` holds the values of the variables, the cost in calls and the one doubt about Discord's index. This file holds what a change to `src/game-log/` must not break.

## Configuration and access

- `GAME_LOG_CHANNEL_ID` and `GAME_LOG_WEBHOOK_ID` are the snowflakes of the channel and of the webhook that posts there, never the webhook's URL, a secret the panel does not hold. `parseGameLogEnv`, in `src/game-log/env.ts`, gives `{ gameLog: null }` for both unset or empty, refuses one without the other by the name of the missing one and a value that is no snowflake by the name of its variable, never its value (`src/game-log/env.test.ts`). `next.config.ts` parses them at build when `VERCEL` is set, so a half set pair fails the build, and `configuredGameLog()` parses them again at the first request elsewhere. A channel read without its webhook would take any author's line for the game server's, which ADR 0010 forbids, so a half set pair is a misconfiguration rather than a game log left out (decided by the agent on 2026-11-06, on #394, for Gilles to review, since #394 says only that the channel and the webhook's ID enter the configuration).
- The values are in `docs/game-log.md`, **Configuration**. Setting them in Production and Preview on Vercel is Gilles' step, then a redeploy, since a variable reaches a deployment at its build (`.claude/rules/env.md`, **Variables**).
- Only a staff member who views the channel on Discord has the link and the page. The page starts with `requireStaffMember`, then `readGameLogForStaff`, in `src/game-log/read-game-log-for-staff.ts`, which answers `unconfigured` for a game log left out of the configuration, `hidden` unless `canViewChannel` says the staff member views the channel (`.claude/rules/staff.md`, **Channel visibility**), and otherwise the page read; the page only calls `notFound()` for `hidden` (`src/game-log/read-game-log-for-staff.test.ts`). That runs in the part of the page under `<Suspense>`, so that the static `metadata` stays and the not-found page of a staff member who does not view the channel renders beside the navigation, under the tab « Journal du jeu – Panel de Shor », as `/records`' does (`e2e/game-log.test.ts`).
- A game log left out of the configuration shows no link, and its page, which the whole staff reaches by its URL, says « Le journal du jeu n’est pas configuré pour ce serveur Discord. » after the staff check alone, since there is no channel to view (`GameLogNotConfigured`; decided by the agent on 2026-11-06, on #394, for Gilles to review, since #394 says only « Pour les autres, c'est la page introuvable »).
- Its link in the navigation, and what the layout reads for it: `.claude/rules/staff-navigation.md`, **The layout's reads and client leaves**. The permissions the page needs, and what it does without them: `docs/discord.md`, **The application's permissions**.

## Reading

- `readGameLog(discord, { channelId, webhookId }, searchParams)`, in `src/game-log/read-game-log.ts`, scans the channel with the webhook as `author_id`, serving one term as `content` when a filter can be served (**The filters**), and asks no member, no user and no other route.
- It checks `author.id` and `channel_id` again in memory, since ADR 0010 found that a webhook's message carries the webhook's ID as its author's, and a forged line must not pass if the search lets it through (`src/game-log/read-game-log.test.ts`, through a fake that ignores `author_id`).
- The time of a line is its message's date, taken from its ID, never the embed's timestamp: the period and the cursor, which the search serves by message IDs, then agree with the day under which the page groups the line (decided by the agent on 2026-11-06, on #394, for Gilles to review).
- Pages go by cursor: `before` holds the ID of the last line of a page, which `cursorParamOf` of `src/ui/filter-params.ts` reads as it does the audit log's, and « Revenir aux plus récents » drops it; the page ends on « Jusqu’au <date> » as the audit log's does; « Plus anciens » and the page that its read cuts short follow `.claude/rules/discord-message-scan.md`. A cursor that is no snowflake counts as absent.

## The lines

- `parseGameLogMessage`, in `src/game-log/parse-game-log-message.ts`, reads a line in the layout of the script that Anaisenkit gave Gilles (ADR 0010, **What a game log line holds**): the title `<category> · <action>`; a first field named after the character, whose value is `compte <n>` and, on a second line, `Cible : <n>` when the action has a target; a field `Lieu`; the footer `Shor · <hash>`. The script is an example with fixed values, not the game server's code, so the parser reads that layout first and stays tolerant of every other place a piece may sit.
- The character's field is the field whose value starts with `compte <n>` on its first line, found by that value and not by its name or its position, and looked for before the author's name and the lines of the description, so that its `Cible` is read whatever other piece holds a `compte`, which then stays raw under the event (`src/game-log/parse-game-log-message.test.ts`, #412). An action is everything after the title's first separator, so `administration:workshop:create` and `déconnexion` stay whole.
- Failing that, the parser looks for the character and the game account in a field's value (`<character> · compte <n>`) or name, then in the author's name, then in the lines of the description, the first found winning; for `Cible`, `Motif` and `Lieu` among the fields' names, the lines of the character's field and the labelled lines of the description (`Label : value`, whatever the markdown around the label); and it takes the identifier from the end of the footer after a `·`. A layout it does not know shows as a line out of format rather than a wrong line (decided by the agent on 2026-11-06, on #412, for Gilles to review, over dropping the earlier readings, since the script is an example).
- `Motif` is read when a line carries one, although the script shows none. The script's message with no embed, whose content is the place then `Shor · <hash> | Hier à 17:23`, stays a raw line, its content as its title, until the game server is known to post one.
- A line is in format when its title has a category and an action; every other piece is optional and shown only if found. What the parser does not recognise is not dropped: it shows raw under the event, in the order Discord shows it, so that no text Discord shows is lost (`GameLogEvent.extra`; `src/game-log/parse-game-log-message.test.ts`, #394). A line that is not in format, an embed with another title or a message with no embed, shows its title, or its content when it has no embed, and each other text as it was written, without failing the page. Either keeps its link to Discord. An embed's timestamp, its images and its colour are not text of the line and are not shown (decided by the agent on 2026-11-06, on #394, for Gilles to review, after the review of #394).
- The game account is a number, not a link to a record, until the game links it to a Discord account (`docs/agents/open-questions.md`). Every detail of a line takes `wrap-anywhere`, so that a place, a reason or a name of any length wraps at 360 px (`e2e/responsive.test.ts`, with a reason of 300 characters, a place of 120 and a raw title of 150).
- The icons by category, `GAME_LOG_CATEGORIES`, are the agent's, #394 asking for none (decided by the agent on 2026-11-06, on #394, for Gilles to review).

## The filters

- `gameLogFiltersOf` reads `category`, `action`, `character`, `account`, `target`, `cell`, `plugin`, `reason`, `text`, `from` and `to` from the address, with the shared `textParamOf` and `dayParamOf` of `src/ui/filter-params.ts`; an invalid one, empty, blank, repeated, with no word in it where words are searched, or a day that does not exist, counts as absent. `category` is `administration` or `characters`, English slugs since a URL counts as a file name; `cell` is a form ID in hex of 1 to 8 digits, with or without `0x`, kept as typed; `account` is a number of 1 to 20 digits, kept as typed, its zeros included, since it is compared with the line's and asked of Discord as the game server writes it (a line `compte 0042` is found by `0042` and not by `42`, which Discord's search could not find in it either; decided by the agent on 2026-11-06, on #395, for Gilles to review). An action, a character, a target, a reason, a text or a plugin with no letter or digit in it counts as absent too, since it would match every line, and `reason` and `text` hold `MAX_SEARCHED_TEXT_LENGTH` characters at most. The address writes them in that order, then `before`, which `gameLogHref` gives the pills, the form, the Sheet, the chips and the pagination alike.
- The pills are « Tout », « Administration » and « Personnages », the two categories seen: ADR 0010 says that the full lists of categories and actions are not known. #395 waits on a list that does not exist (#391's questionnaire), so the pills are a table of two entries, `GAME_LOG_CATEGORIES` of `src/game-log/game-log-categories.ts`, which holds each category's label, its URL key and its icon, and which `categoryKeyOf` reads with one lowercasing for the filter, the pills and the tile, so that a category the game server posts later is one more entry when someone learns of it. Until then a line of another category shows under « Tout » with the generic icon and is found by its text or its action, and no pill « Autres » gathers the lines that no pill names, since nothing says that any exists (decided by the agent on 2026-11-06, on #395, for Gilles to review). A line is in a category when its title's category equals the pill's label, whatever the case. A pill keeps the other filters and drops the cursor, and « Réinitialiser » shows once any filter is set. The category is the one filter that is no chip and that « Filtres » does not count, since its pill says it, as the audit log's type and the Bot log's family are; the form and the Sheet keep it in a hidden field.
- The fields are « Action », « Personnage », « Compte de jeu », « Cible », « Cellule », « Plugin », « Motif », « Texte », « Du » and « Au », in that order. « Action », « Personnage », « Cible » and « Motif » are texts of whole words, not choices, as the Bot log's action is: every word typed must be among the words of the line's action, character, target or reason, whatever the case and with the accents, so that « heal » finds `administration:heal` and « hea » finds nothing, and an action the game server adds is found with no change here, which a closed list could not do, since ADR 0010's lists are unknown (decided by the agent on 2026-11-06, on #395, for Gilles to review). The game account is the number alone, equal to the line's, with no link to a record. « Texte » finds the words in one text of the message, as the Bot log's does, and a text with no word in it counts as absent: the page checks the text in memory, and a text that matches everything would be a filter that does nothing. `wordsOf` joins the letters around U+2019 alone, so a name typed with the ASCII apostrophe is not known to join (`docs/discord.md`, **The fake**; inferred, not tried).
- The place is two fields, « Cellule » and « Plugin », read out of the line's `Lieu`, `<form ID in hex>:<plugin> · <x>, <y>, <z>` (ADR 0010; `placeOf`, `src/game-log/game-log-place.ts`). #395 says « par cellule ou par plugin »: two fields make the two combine in AND and cannot be mistaken for each other, where one field would have to guess which a text means (decided by the agent on 2026-11-06, on #395, for Gilles to review). The cell equals the line's form ID whatever its case, its `0x` prefix and its leading zeros; the plugin is any part of the plugin's name, whatever the case, since the plugins are the server's load order, which the panel does not hold, so that no closed choice is possible. « Cellule » is #395's word: ADR 0010 infers that the form ID is a worldspace or a cell local to its plugin, so it may name a worldspace. A place that does not follow that format, and a line with no place, match neither field and stay findable by the text.
- A line out of format, an embed with another title or a message with no embed, matches only the text and the period, and any other filter drops it. A line in format whose category no pill names matches the other filters like any other.
- Discord's search serves one text, so the read asks for one term, the first of the game account, the longest term of the target, of the character, of the text, of the reason and of the category's label (`servedTermOf`), and checks every filter again in memory, exactly, over the messages it gives (`keptEntry`). The term is a necessary condition of its filter, so Discord hides no line that passes. The action, the cell and the plugin are never the term: the game server writes `administration:heal` and `3c:Skyrim.esm · …`, which Discord's index may keep as one word, so that a search for « heal » or « Skyrim » would hide lines that the page keeps (**inferred, unproven**; `docs/game-log.md`, **The colon and the dot**). An action, a cell or a plugin alone so scans on, up to 4 searches, and a page that stays short is cut (`.claude/rules/discord-message-scan.md`).
- The form's layout, its Sheet, its chips and the skeleton are in `docs/responsive.md`, **`/game-log`**.

## Tests

- `src/game-log/` is tested on the fake Discord, then through `react-dom/server`: `gameLogMessage` poses a line in the format above and `gameLogChannel` a channel that given roles view, both test helpers that stay in test files (`.claude/rules/discord.md`, **The fake**). `/game-log` is also crossed by `e2e/responsive.test.ts` and `e2e/skeletons.test.ts`; its logout flow sets a viewport 6,000 px high (`docs/game-log.md`, **Tests**).
