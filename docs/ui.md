# The interface's shared parts

The evidence behind `.claude/rules/ui.md`, `.claude/rules/ui-theme.md` and `.claude/rules/ui-overlays.md`: what the copied components were found to do, the measures of the theme, the contrast ratios, and the trials of the motion, the toast and the touch sizes. The rules say what to do; this file says how it was known. #129 settled the identity, #221 and #222 the Hydromel palette, #224 to #236 the pages built on it, #227 the toast, #355 to #362 the responsive work.

The `node_modules` citations are those of Next.js 16.4.2, React DOM 19.3.0-canary-278794d7-20261002, Base UI 1.9.0 and Tailwind 4.3.3: an update of a package re-reads the citations that name it (`.claude/rules/dependencies.md`, **Docs that name a version**).

## The theme a staff member chooses

- Tailwind 4.3.3 leaves `light-dark()` as it is though it targets Chrome 111 and Safari 16.4 (`node_modules/.pnpm/@tailwindcss+node@4.3.3/node_modules/@tailwindcss/node/dist/index.js`, #225), which is why `globals.css` holds copies of the blocks under `data-theme`. - Without `suppressHydrationWarning` on `<html>`, a throwaway run of `e2e/theme.test.ts` under `next dev` logged « A tree hydrated but some attributes of the server rendered HTML didn't match the client properties » twice, and with it no line about hydration, beside Next.js's own warning about server caches (2026-10-29). - `renderToStaticMarkup` wrote a script's text as it is, escaping `</script` alone (2026-10-29).
- #225 planned `next/script`'s `beforeInteractive` instead, whose App Router version renders, in the body, only a `self.__next_s.push(…)` that Next.js's bootstrap, an `async` chunk, runs before it hydrates (`node_modules/next/dist/client/script.js:274-292`, `node_modules/next/dist/client/app-bootstrap.js:23-49`): with « Sombre » stored, over 10 loads of `/login/logged-out`, `data-theme` was still unset at `DOMContentLoaded` in all 10 and at the first animation frame in 9, against none of 10 with the head's script (a throwaway Playwright probe, 2026-10-29), and the reload of `e2e/theme.test.ts` fails on it.

## Motion

- React keeps the rest of the page, the sidebar included but for the current section's bar, out of a transition: it sets the root's `view-transition-name` to `none` and hides the root's snapshot (`node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.development.js:16392-16411`). `<ViewTransition>` renders from a Server Component as `<Suspense>` does (the staff pages, and the crossfade test of `e2e/staff-header.test.ts`, 2026-10-27), and a `refresh()` runs no view transition (a throwaway test of a write, 2026-10-27). The App Router runs it with no configuration (`node_modules/next/dist/docs/01-app/02-guides/view-transitions.md:50`), a layout that stays mounted across sections fires no `enter` or `exit` (the same guide, `:268`), and a browser without the View Transitions API shows the change without the animation (`:53`).
- `highlight-enter`'s tint is held for half its length so that it shows (Playwright screenshots of a throwaway page, light and dark, 2026-10-27).
- Under reduced motion, on a throwaway page holding the five classes, Chromium ran only opacity, `highlight-enter`'s tint and the blend mode of a swapping pair, where with motion it also moved `slide`'s group and raised `content-enter` (2026-10-27).
- The Toast's copied classes slide a toast in from below and out by 150% of its height, and restack the others, through `transition: transform 500ms cubic-bezier(0.22, 1, 0.36, 1), opacity 500ms, height 150ms` (`src/ui/toast.tsx`, #227). The spinner of a pending button is Tailwind's `animate-spin`, `spin 1s linear infinite`, and the skeleton's pulse the copied `animate-pulse`, `pulse 2s cubic-bezier(0.4, 0, 0.6, 1) infinite` (`node_modules/tailwindcss/theme.css:438`, `:440`, Tailwind 4.3.3).
- The filter sheet of the audit log lists the properties its transitions run when it opens, `opacity` alone under reduced motion and `opacity` and `translate` with motion, as the navigation's menu does, and `translate` came too, in 4 runs of 4, on a throwaway build without `motion-reduce:translate-y-0!` (`pnpm test:e2e e2e/audit-log.test.ts -g "fades in and slides up" --repeat-each 4`, 2026-11-03). The Sheet of `/records` is in `docs/records.md`, **Trials**.
- The Sheet of the navigation's menu slides in and out by `2.5rem` through its copied classes (end to end, 2026-10-27; #137).
- `e2e/skeletons.test.ts` shows the skeletons while `holdDiscord` holds Discord's answers back, and fails with the `<ViewTransition>`s of `SuspenseWithSkeleton` or a skeleton's `motion-reduce:animate-none` taken out (2026-10-28).

## View transitions

The trials behind `.claude/rules/view-transitions.md`, for the React DOM that Next.js 16.4.2 runs the App Router on, `19.3.0-canary-278794d7-20261002` (the `version` of `node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.production.js`).

- React hides the group of a `<ViewTransition>` that a transition leaves unchanged with an animation of no duration and `fill: "forwards"` on `::view-transition-group(<its name>)` (the same file, `:11023-11030`). With a `<ViewTransition>` around the header's name and its skeleton, in `src/app/(staff)/layout.tsx`, which stays mounted, each navigation hid that group, and each such animation stayed in `document.getAnimations()`, finished, once its transition had ended: 1, 2, then 3 after three navigations, while the current section's underline, which every navigation moves, left none. So the wait of `checkAccessibility` never ended, and the crossfade test under reduced motion caught the hidden pair's crossfade (throwaway Playwright test that logged `document.startViewTransition`, the `animate` calls on a `pseudoElement` and `document.getAnimations()`, 2026-10-27, #139). The blocked words', in the page, left none: after an add that moved no other word, React hid the groups of the three words that kept their place the same way, and `document.getAnimations()` was empty once the transition had ended (throwaway Playwright test, 2026-10-28, #166).
- A `<Suspense>` that reveals after a client navigation, as a record's does when Discord answers late, has React hide the page's own `<ViewTransition>` the same way, through an animation on a `::view-transition-group` that this view transition does not hold, so it outlives it, finished, in `document.getAnimations()`, and keeps the page's group at `opacity: 0` when a later navigation makes it exit (throwaway Playwright probe, each call to Discord delayed by 50 ms, on #211's branch and on `main`, 2026-10-28). On CI's runner, a record opened from the search met it once #177 added the history's calls to Discord: `checkAccessibility`, which then waited for an empty `document.getAnimations()`, timed out (run 40777294822), and now waits for no animation still running. The page that exits then vanishes rather than fading out (inferred, #212).
- React marks a `<ViewTransition>` as updated whenever a prop of an element inside it changes, not only when it moves: `setProp` flags every prop it sets (`node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.development.js:21630`, `:22090`), and the commit then marks the nearest `<ViewTransition>` (`:16275-16278`). With each blocked word's `update` set to `slide`, an add crossfaded each word it moved, under reduced motion too (a run of `e2e/blocked-words.test.ts` against `update="slide"`, 2026-10-28); and a removal, which enables every « Retirer » again, names every word, the one that keeps its place included, whose group then runs from and to the same place (throwaway Playwright test, 2026-10-28), so `slide` would crossfade it too (inferred, #166).
- React animates the `enter` or `exit` of a `<ViewTransition>` only when no DOM element sits between it and the top of what a commit inserts or deletes: the commit looks for one through a flag of the inserted or deleted fiber's `subtreeFlags` (`node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.development.js:14378`, `:14597`), which every host element clears from its own (`:13141-13142`). On 2026-10-28, with each blocked word in a `<ViewTransition>` inside a `<ul>` that rendered only with words, the first word added and the last removed started no view transition, while a word added to or removed from a list that already held another started one (throwaway Playwright test that counted the calls to `document.startViewTransition` and logged the fibers React's commit walked, #138).
- An update that comes while a view transition runs, such as the toast a write's leaf adds from its effect once the result commits (`.claude/rules/ui-overlays.md`, **Toasts and failure messages**), has React take the `view-transition-name`s off the elements it named while their animations still run: on 2026-10-29, a throwaway Playwright probe that logged each frame of a word's add read no name on its `<li>` in any frame, though its `::view-transition-new` ran, and `e2e/blocked-words.test.ts`, which read the names off the `<li>`s as it had on `main`, mapped every animation of a write to no word (inferred: React restores the names once work spawned during the transition waits, `spawnedWorkCallback`, `node_modules/next/dist/compiled/react-dom/cjs/react-dom-client.production.js:15873`). So that test records each name as React writes it, through a `MutationObserver` that an init script installs on every page it opens.
- After a full page load, React's streaming runtime reveals what a `<Suspense>` streams through a view transition of its own, which runs `content-enter` since #139, and which the crossfade test with motion caught in place of the navigation's in 1 run of 3 (`--repeat-each 3`, 2026-10-27): so a test that watches the next view transition first waits for the content, then for `document.activeViewTransition` to be `null` (`.claude/rules/e2e.md`, **The fixtures**).

## Toast

- A refused write and a page shown again add no toast, as `e2e/blocked-words.test.ts` and `e2e/sanctions.test.ts` prove, both red with the hook's two guards taken out (2026-10-29). `<Activity>` reruns the effects of a page it shows again (`node_modules/next/dist/docs/01-app/02-guides/preserving-ui-state.md:70`).
- Added from the action, before the commit, a toast left the first blocked word added without its view transition (`e2e/blocked-words.test.ts`, 2026-10-29), since Base UI keeps its toasts in a store read through `useSyncExternalStore` (`@base-ui/utils` 0.5.0, `store/useStore.js:25`), whose updates React renders synchronously (inferred).
