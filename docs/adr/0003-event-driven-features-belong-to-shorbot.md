# The Admin Panel never connects to Discord's gateway; event-driven features belong to ShorBot

The Admin Panel only calls Discord's REST API. Any feature that must react to Discord events, such as automatic sanctions, message logs or reaction roles, is built in ShorBot, loanspac's bot, behind an HTTP API agreed with loanspac before either side writes code for it. Shor keeps a single bot connected to the gateway. Decided by Gilles on 2026-10-23.

The panel's own Discord application (ADR 0002) does put a bot user on the Discord server, but that user never connects to the gateway: it only makes REST calls, when a staff member uses the panel. The docs call it the panel's application, never a bot. Clarified by Gilles on 2026-10-23, while grilling #7.

The panel's application may also answer interactions, which Discord sends over HTTP to the Interactions Endpoint URL set in the Developer Portal: the buttons, select menus and modals of the messages the panel posts, and slash commands that do what a page of the panel does. Discord wants "an initial response within 3 seconds", and "Interaction tokens are valid for 15 minutes" for the rest (https://docs.discord.com/developers/interactions/receiving-and-responding, read 2026-10-27). That opens no gateway connection, so ShorBot stays the one bot on it, and the two ways "are mutually exclusive" for an application (same page). Anything else Discord does still reaches only the gateway, since its webhook events carry no event of a Discord server, such as a member joining or a message sent (https://docs.discord.com/developers/events/webhook-events, read 2026-10-27): a role given on a reaction is ShorBot's, a role menu of buttons on a message the panel posted is the panel's. Decided by Gilles on 2026-10-27, while grilling the features that follow the MVP.

Of the Bot's expected features, which the POs listed and Gilles relayed on 2026-10-23 (#4), the panel's application takes those that need no gateway once an interaction triggers them, and ShorBot keeps the one that does. Support tickets, opened from a select menu and closed through a button and a modal, are the panel's. So is the Membre role, given through a button « J’accepte le règlement » on a message the panel posts rather than on a reaction, and so are the names of the two voice channels that show the game servers' state, which a staff member sets from the panel until the game can tell it. The temporary voice channels stay ShorBot's: knowing that a member joined « Créer un vocal », or that a channel has stayed empty for a minute, takes the gateway, since REST reads one account's voice state at a time and lists no channel's (https://docs.discord.com/developers/resources/voice, read 2026-10-28). Decided by Gilles on 2026-10-28, who takes the first three over from loanspac: ShorBot's branches `feat/ticket` (11392fd) and `feat/status` (67b8c93), both of 2026-10-27, held a first version of the tickets and a slash command that toggles the status by hand.

## Considered Options

- **The panel's own Discord application runs a gateway bot of its own on the VPS.** Independent from loanspac, but two bots doing neighbouring jobs, and it needs sudo and Node on a shared VPS this project does not administer. The VPS stopped being a reason once Gilles administered it, and the decision holds on the first one (Gilles, 2026-10-27).
- **The panel connects to the gateway with ShorBot's token.** Two sessions for one bot, which risks handling each event twice.
- **The Bot's whole list stays in ShorBot.** loanspac had started the tickets and the status there, in Python, on the VPS. But a warning, a timeout and a kick are contested through a support ticket (`docs/agents/open-questions.md`), so the sanction, its direct message, the ticket that contests it and the record of the account would sit on two sides of an API that ShorBot does not have (Gilles, 2026-10-28).

## Consequences

- The first such feature brings a link from the panel to ShorBot, which exposes none: ShorBot was restarted on discord.py, and at `ef620dc` (2026-10-27) its `main.py` holds `/help` and `/ping` and no HTTP API (https://github.com/ShorRP/ShorBot/blob/ef620dc/main.py). Where that API listens and how it knows the panel are agreed with loanspac then.
- What the panel can do with plain REST calls, such as AutoMod rules, roles or channels, stays in the panel.
- The panel's Interactions Endpoint comes before #150, the wave that first planned it. It must be "a public endpoint that Discord can reach", which answers a PING and checks each request's signature before the URL saves, and Discord keeps sending it "automated, routine security checks", some with invalid signatures, then removes a URL that fails them (https://docs.discord.com/developers/interactions/overview, modified 2026-07-22). An application holds one such URL, which `PATCH /applications/@me` changes (https://docs.discord.com/developers/resources/application, modified 2026-07-21). So "Shor Panel Dev" reaches `pnpm dev` through a Cloudflare quick tunnel, which needs no account and whose URL changes at each run (https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/, updated 2026-09-30), and a script points the application at it each time; its previews receive no interactions (Gilles, 2026-10-28). ngrok's free plan, which keeps one domain, was set aside: it needs an account, and its pricing calls part of it a "one-time free trial credit" (https://ngrok.com/pricing, read 2026-10-28), which **Costs** keeps out. A protected preview reached through Vercel's Protection Bypass for Automation, or one a Deployment Protection Exception makes public, was set aside too: the first secret opens every deployment of the project, and both make each try wait on a push (https://vercel.com/docs/deployment-protection, updated 2026-09-15).
